# Ceramic mixer and browser setup help

Approved direction: Ceramic Signal (proposal 06), selected by the owner on 2026-11-06. The owner also requested a discreet header style switch and a question-mark button teaching browser extension installation. This is authorization to implement the design.

## Appearance

Make Ceramic the default: porcelain surfaces (#F5F7FA, #DCE2EA), cobalt controls (#244EE8), ink text (#17213A), secondary text (#8290A6). Use system typography, clear horizontal sliders, circular mute buttons, restrained depth, and thin separators. Keep the existing Retro style available from a small header palette menu; persist the selection with AppStorage. Style changes must reuse the live MixerModel and ChromeTabModel so active audio routes and settings continue unchanged.

Group Chrome child tabs under the Chrome master when that app is present. Otherwise show the browser connection panel separately. Preserve all capabilities, pending state, disconnected state, unsupported-player explanations, tab play/pause, mute, Boost, and saved volumes. The output label reflects the actual output; it is not an output selector.

Use the Ceramic speaker-cone icon for the application and Chrome extension, generated by the repository's editable icon script. Retain the Retro rendering and controls as a selectable appearance.

## Setup help

A discreet accessible question-mark button in either header opens a native installation sheet. Explain that the current integration supports Google Chrome. Include steps to open chrome://extensions, enable Developer mode, load the bundled extension folder, copy the extension ID, run the bundled bridge installer against the current app path, allow site access, and reload existing pages if needed. Provide folder/open-page buttons and a copyable command generated only for a valid extension ID. Quote paths safely, including spaces and apostrophes. Explain how to reload an existing installation without changing its extension folder/ID, and show connection state. Reuse the same sheet from Settings and the existing Retro setup action.

Do not change Chrome host registration or browser permissions automatically. The help sheet guides the user through those explicit installation steps.

## Verification

Keep macOS 14.4+ and SwiftUI; no external dependencies. Build and run existing Swift tests, plus focused tests for extension ID validation and command quoting. Render both themes with normal, boosted, empty, connected and disconnected preview data, and render the help sheet. Inspect PNGs for truncation, contrast and overflow. Build a complete signed app bundle and confirm help resources and icons are present. UI previews must not touch live audio or browser sessions.
