# Ceramic Mixer Implementation Plan

> Execute inline in this session, following the owner's implementation request. No delegated agents are needed.

**Goal:** Ship the selected Ceramic appearance, a discreet persistent style switch, and in-app Chrome extension installation help.

**Architecture:** Keep MixerModel and ChromeTabModel unchanged. A small appearance wrapper selects the existing Retro view or a new Ceramic view. Both use one header accessory group and one Chrome tab control implementation. Setup help owns instructions and safe command generation, with no automatic installation.

**Tech Stack:** SwiftUI, AppKit, Swift Package Manager, repository-native Python icon drawing.

**Spec:** docs/superpowers/specs/2026-11-06-ceramic-design.md

## Global Constraints

- macOS 14.4+; no external dependencies.
- Reuse the live audio/browser models across appearance switches.
- Default to Ceramic and save the user's appearance choice.
- Keep tab capability gates, pending gain display, disconnect and unsupported-player feedback.
- Never change host registrations or browser permissions automatically.
